# 온도 기반 자동 제어 — 0.4.2

## 현재 목표: 70°C

CPU/GPU 중 더 높은 온도를 기준으로 **60°C부터 해당 전원의 최대 풍량**을 사용해 70°C 도달 전에 대응합니다.
팬이 가속하는 시간을 고려한 여유이며, 최대 풍량 상태는 **57°C 미만**에서 해제합니다.
이 규칙은 성능/저소음 곡선보다 우선합니다. GPU 기준만 선택하면 CPU는 제어 기준에 포함되지 않습니다.
상단/트레이에 목표 70°C를 표시하고 70°C에 도달하거나 넘으면 상태를 표시합니다.
CPU/GPU 부하·주변 온도·노트북 냉각 구조 때문에 외장 쿨러만으로 **70°C 이하를 보장할 수는 없습니다**.
전원별 RPM 상한을 넘기거나 CPU/GPU 전력/클럭 설정을 자동 변경하지 않습니다.

## 원본 분석 및 구현

원본은 CPU/GPU 온도 중 최댓값에 단계형 성능/저소음 곡선을 적용하고 주기적으로 목표 RPM을 보낸다.
온도 센서는 LibreHardwareMonitor/PawnIO 계열을 사용하며 곡선 계산은 PC에서 수행한다.
이 확인을 위해 기존 분석 사본의 소스만 읽었으며 제조사 EXE/DLL/드라이버는 실행하지 않았다.

새 앱은 같은 용도의 자체 곡선 계산과 온도 수집을 구현했다.
자동 진입 `0x23` 후 임시 RPM 명령 `0x21`을 쓰고, 중지 시 원래 모드/RPM을 복원한다.
수동 모드에서는 거부됐던 `0x21`이 자동 모드에서 성공하는 것을 실물에서 확인했다.
반복 자동 제어에 `0x26`을 사용하지 않아 4단계 저장 속도를 계속 덮어쓰지 않는다.

GPU/NVIDIA는 Windows System32의 기존 `nvml.dll`에서 읽는다.
파일의 Microsoft WHQL 서명 유효 상태와 `nvidia-smi` 온도 조회도 확인했다.
Intel CPU는 별도로 구성된 공식 PawnIO가 있을 때 CPU 패키지 온도 레지스터를 읽는다.
CPU 값이 없으면 0°C로 취급하지 않고 사용할 수 없는 센서로 표시한다.
공식 드라이버의 기본 접근 권한을 유지하며 CPU 읽기에는 관리자 실행이 필요하다.
일반 실행에서 접근이 거부되면 **CPU 온도 권한으로 다시 실행** 버튼을 표시한다.
버튼을 직접 누르면 현재 자동 제어를 중지/복원하고 같은 실행 파일을 Windows 관리자 승인으로 다시 실행한다.

## 제어 규칙

| 조건 | 동작 |
| --- | --- |
| CPU/GPU 기준 | 두 센서 중 더 높은 온도. 둘 다 유효해야 시작 가능 |
| GPU 기준 | 유효한 NVIDIA GPU 온도만 사용. CPU 온도를 반영하지 않음을 화면에 명시 |
| 성능/저소음 | 분석한 BS2 Pro 전원별 단계형 곡선 적용 |
| 70°C 목표 | 60°C부터 최대 풍량 유지, 57°C 미만에서 해제. 성능/저소음보다 우선 |
| 70°C 도달/초과 | 계속 최대 풍량, 목표 도달/초과 표시. 실제 온도 제한 보장은 아님 |
| 온도 상승 | 새 단계로 즉시 상승 |
| 온도 하강 | 경계보다 2°C 낮아진 뒤 감소 |
| 90°C 이상 | 최대 풍량, 87°C 미만에서 고온 유지 해제 |
| 센서 누락/비정상/8초 초과 | 해당 전원의 최대 풍량 |
| 전원 상한 | 일반 2700 / QC 3300 / PD 4000 RPM |
| 자동 중지/정상 종료 | 자동 시작 전 모드와 RPM 복원 |
| USB 연결 끊김 | 자동 중지, 재연결 후 사용자가 다시 시작 |

온도는 약 2초마다 수집하고 약 1초의 제어 주기마다 임시 목표 RPM을 갱신한다.
실제 팬은 목표 변경 직후 즉시 같은 RPM이 되지 않고 천천히 가속하므로 진단은 수렴 과정도 확인한다.
수동 RPM 적용과 자동 제어가 동시에 속도를 바꾸지 못하도록 화면에서 차단한다.

## 현재 PC에서 확인한 결과

- Intel i7-13650HX / NVIDIA RTX 4060 Laptop GPU.
- Windows ACPI/WMI CPU 온도 경로는 지원하지 않거나 유효 값이 없었다.
- 0.2.0 시험 시 PawnIO 장치가 없어 CPU를 읽지 못했다. 이후 사용자가 설치/설정을 허용해 공식 PawnIO 2.2.0을 설치했고 CPU 온도를 실제로 읽었다.
- 설치 파일은 공식 릴리스 SHA-256과 유효한 `namazso.eu` Authenticode 서명을 확인했다. 설치된 드라이버도 Microsoft WHQL 서명 유효 상태를 확인했다.
- GPU는 실제 약 49~54°C를 읽었다. 실기 자동 시험에서 53~54°C → 목표 2100 RPM 적용 성공.
- 자동 중지 후 당시 기존 목표 1400 RPM 및 저장 속도 4개가 유지/복원됨을 확인했다.
- WPF 자동 시작/중지, 수동 적용 차단, 기존 RPM 복원, 최소 창 크기 레이아웃 확인.
- 프로토콜/온도 테스트 24개 통과, Release 빌드 경고/오류 0개.
- 일반 권한에서 CPU 접근 거부 및 권한 재실행 버튼 표시, 유효 CPU가 없을 때 CPU/GPU 자동 시작 차단도 확인했다.
- 관리자 실행에서 CPU Package 약 61~78°C, GPU 약 49~50°C를 실측했다.
- CPU 78°C / GPU 50°C → 높은 CPU 온도 기준 목표 2700 RPM 적용, 실제 2600 RPM까지 점진 상승(진단 허용 오차 ±150 RPM) 확인 후 기존 목표 1400 RPM 및 4단계 저장 속도 복원.
- WPF에서도 CPU 60°C / GPU 49°C → 목표 2400 RPM 표시, CPU/GPU 자동 시작/중지와 기존 목표 복원 시험을 통과했다.
- 초기 7초 수렴 검사는 실제 가속 시간을 충분히 기다리지 못해 실패했으나 설정은 복원됐다. 이후 최대 35초 동안 회전수를 관찰하는 검사에서 통과했다. 목표값 적용 성공과 실제 회전수 상승 검증을 구분했다.

## 선택 사항: CPU 센서 설정

GPU 기준만 사용할 경우 추가 설치가 필요 없다.
현재 PC에는 공식 서명판 PawnIO 2.2.0 설정을 완료했다. 다른 PC에서 CPU까지 반영하려면
관리자 권한으로 **공식 서명판 PawnIO**를 별도로 구성해야 한다.
앱이나 게시 도구가 설치 파일을 실행하거나 드라이버를 시작하지 않는다.

1. [PawnIO 공식 사이트](https://pawnio.eu/)에서 공식 서명판 설치 안내를 확인한다. 무서명/unrestricted 판을 사용하지 않는다.
2. 설치 후 앱을 실행한다. CPU 권한 안내가 표시되면 **CPU 온도 권한으로 다시 실행** 버튼을 눌러 Windows 승인을 허용한다. 드라이버의 접근 권한은 변경하지 않는다.
3. 실제 CPU 값이 읽힐 때 `CPU / GPU 중 더 높은 온도`를 선택하고 자동 제어를 시작한다.
4. CPU 값이 여전히 없으면 GPU 기준만 사용하며 이를 전체 CPU/GPU 제어 성공으로 간주하지 않는다.

CPU 모듈은 제조사 설치 폴더의 파일을 복사하지 않았다.
[공식 PawnIO.Modules 0.2.11 릴리스](https://github.com/namazso/PawnIO.Modules/releases/tag/0.2.11)의
서명된 `IntelMSR.bin`을 고정 해시로 포함하고 대응 소스와 LGPL 고지를 함께 제공한다.
앱은 모듈의 CPU 온도 관련 읽기 경로만 호출하며 MSR 쓰기 기능을 노출하지 않는다.

자세한 구성요소는 [고지](../THIRD_PARTY_NOTICES.txt)와 [모듈 소스](../third_party/PawnIO.Modules/0.2.11/IntelMSR.p)를 따른다.
