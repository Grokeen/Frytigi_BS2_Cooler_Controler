# BS2 Cooler 구현 및 검증 기록

## 0.2.0 — 온도 자동 제어 추가

온도 표시, 성능/저소음 자동 곡선, 고온/센서 오류 시 최대 풍량, 자동 중지/종료 시 이전 설정 복원을 추가했다.
GPU 실측 53~54°C에 따른 2100 RPM 적용과 기존 1400 RPM 복원을 실물/WPF 화면에서 확인했다.

CPU 드라이버의 자동 설치/시작은 하지 않으며 현재 PC는 미설정이어서 CPU 실측은 미검증이다.

## 구현

제조사 프로그램에 대한 보안 우려를 반영해 제조사 코드의 로드/실행 경로를 제거했다.
배포 앱은 자체 .NET 코드와 Windows 기본 HID API로 BS2 Pro를 직접 제어한다.

| 프로젝트 | 역할 |
| --- | --- |
| `src/Bs2Cooler.Core` | 명령 생성, 길이/체크섬 검증, RPM/상태 해석 |
| `src/Bs2Cooler.Windows` | 장치 열거, 인터페이스 검증, 비동기 USB I/O |
| `src/Bs2Cooler.App` | 한국어 WPF 화면, 주기적 조회, 수동 설정, 재검색 |
| `tests/Bs2Cooler.Tests` | 실제 캡처 패킷, 손상/절단/경계값 테스트 |
| `tools/Bs2Cooler.Diagnostics` | 읽기 전용 조회, 변경/복원 실기 시험 |
| `tools/Bs2Cooler.UiSmoke` | WPF 연결/실제 데이터/최소 크기 레이아웃 검증 |

외부 패키지 참조는 0개다. 제조사 DLL/프로세스/IPC와 HidSharp를 사용하지 않는다.
네트워크 클라이언트, 외부 프로세스 실행, 드라이버/서비스 설치, 자동 업데이트,
관리자 권한 요청도 없다. 네이티브 DLL 검색은 System32로 제한하고
`hid.dll`, `setupapi.dll`, `kernel32.dll`만 직접 호출한다.

`.analysis/`의 초기 비교용 프로젝트는 제조사 SDK를 실행했던 이전 분석 자료다.
새 앱/테스트/진단의 빌드·실행에 필요하지 않고 배포에도 포함하지 않는다.
기존 프로그램의 악성 여부와 기존 PC 감염 유무는 이 통신 구현으로 판정하지 않는다.

## 통신 및 정확성

- 실물 USB `37D7:1002`, Usage `FFA0:1`, 펌웨어 `0.0.3.3`
- 입력 33바이트(`00 03 5A A5`), 출력 32바이트(`00 5A A5`)
- 수신 길이/가산 체크섬 검증, 명령 직렬화 및 명령 ID 일치 확인
- 1.5초 응답 제한, 비동기 읽기 취소/연결 종료 처리
- 6초 내 전원 상태가 없거나 쿨러가 꺼져 있으면 속도 변경 거부
- 전원에 따른 RPM 상한 검증, 시작/재연결 시 설정 쓰기 없음

단독 RPM 명령 `0x21`은 실물 수동 모드에서 응답 `2`로 거부됐다.
앱은 수동 제어 성공이 확인된 **단계+RPM 명령 `0x26`만 사용**한다.
처음 시험에서 이 거부로 조명 복원이 중단됐으나 즉시 기존 설정을 복원했다.
진단의 복원 작업을 각각 독립적으로 수행하도록 수정한 뒤 전체 시험을 다시 통과했다.

## 남은 조건

실물 시험은 일반 전원(최대 2700 RPM), 수동 모드, 이미 켜진 USB 장치에서 수행했다.
QC/PD 고속 회전, 스마트 모드 해제, 실제 케이블 분리/절전 복귀,
장치 전원까지 껐다 켜는 냉간 시작은 아직 실기 시험하지 않았다.
이 조건의 오류/재검색/상한 처리는 구현된 부분과 실물 검증된 부분을 구분한다.

온도 센서/자동 곡선, Bluetooth, RGB 색상/효과 편집, 펌웨어 업데이트는 이 버전의 범위 밖이다.
쿨러 수동 제어를 위해 별도 드라이버를 설치하지 않는다.

Windows HID 버퍼 규칙은 [Microsoft HIDP_CAPS 문서](https://learn.microsoft.com/en-us/windows-hardware/drivers/ddi/hidpi/ns-hidpi-_hidp_caps)에 따라 구현했다.
