# BS2 Cooler 구현 및 검증 기록

## 0.4.4 — 프로젝트 최상위 실행기

게시 스크립트가 프로젝트 최상위에 실제 `BS Pro Controller.exe`를 생성하고, 패키지/설치용
`Bs2Cooler.exe` 및 ZIP 내부 EXE와 같은 SHA-256인지 검사한다. GitHub 빌드 산출물과 Release에도
요청한 이름의 단일 EXE를 포함한다. 생성 바이너리는 Git에서 제외하며 소스만 복제하면 게시 스크립트로 생성한다.
파일명과 배포 경로를 개선한 버전으로, 창 제목·내부 어셈블리·로그인 작업·온도/USB 제어는 기존 동작을 사용한다.

로컬 Release 빌드 경고/오류 0개, 기존 40개 테스트와 게시/패키지 해시 검사를 통과했다.
이름이 바뀐 최상위 EXE를 실행해 기존 앱 창 열기/단일 인스턴스/자동 제어 유지와
기존 앱이 없는 상태의 관리자 실행/CPU·GPU 수집/자동 제어 시작도 확인했다.
최종 배포/설치 소스와 로컬/원격 해시는 [작업 보고서](WORK_LOG.md)에 기록한다.

## 0.4.3 — 공통 다크 테마와 이벤트 애니메이션

WPF 기본 콤보박스의 흰색 표면/목록을 공통 ControlTemplate로 바꾸고 선택 글자의 검은색 지정을 제거했다.
입력창·탭·체크박스·슬라이더·스크롤바·도움말도 같은 색상과 키보드 포커스 표시를 사용한다.
메인/RGB의 기본 Windows 창 테두리는 유지하면서 DWM 다크 제목 표시줄을 요청하고 트레이 메뉴는
같은 팔레트의 WinForms renderer를 사용한다. 외부 UI 패키지를 추가하지 않았다.

버튼 가리킴/누름, 탭/창/목록 열기, 연결/작업 상태 변경에 100~220ms의 일회성 효과를 추가했다.
Windows ClientAreaAnimation이 꺼져 있으면 이동/페이드 효과를 생략한다.
온도/RPM과 주기적인 자동 상태 수치에는 효과를 붙이지 않았다.

실물 WPF에서 네 콤보박스의 어두운 표면/목록, 키보드 선택, RGB 입력/슬라이더/체크 표시,
상태 효과 완료/생략, Windows 11 다크 제목 표시줄 요청 성공을 확인했다.
RGB 장치 적용/로컬 저장/원래 팔레트 복원, CPU/GPU 자동 시작/중지/목표 복원과 최소 크기 배치를 통과했다.
Release 빌드 경고/오류 0개, 기존 프로토콜/온도/RGB 40개 테스트 통과. 고대비/다중 DPI/실제 재부팅은
이번 UI 검증 범위에 포함하지 않았다. PR #8/main/Windows release 빌드 성공, v0.4.3 공개 ZIP/EXE 다운로드
해시 검증과 Program Files 설치를 완료했다. 로그인 CPU/GPU 자동 제어 On을 유지하고 새 창을 열어 두었다.
배포/설치 소스는 `72af254aab46fc843f8369ab1dce52a7cc3c934f`이며 최종 문서 커밋과 구분한다.
자세한 날짜·시간 및 게시 결과는 [작업 보고서](WORK_LOG.md)에 기록한다.

## 0.4.2 — 70°C 목표 제어

사용자 요청에 따라 60°C부터 전원별 최대 풍량을 우선 사용하고 57°C 미만에서 해제한다.
목표 70°C 도달/초과를 화면에 표시한다. CPU/GPU 부하와 냉각 능력 때문에 실제 온도 상한을 보장하지 않는다.
전원별 RPM 제한, 센서 오류 시 최대 풍량, 90°C 고온 보호와 자동 중지 복원을 유지했다.
전원 3종/프로필 2종의 경계·유지·복귀·리셋·오류 우선 테스트를 추가해 총 40개를 통과했다.
실물 WPF의 정상 자동 제어/복원, 가상 73°C 데이터의 경고 표시, GitHub 빌드/게시와 다운로드 해시를 확인했다.
고부하의 지속 70°C 이하 유지는 시험하지 않았으며 CPU/GPU 전력·클럭 설정은 변경하지 않는다.

## 0.4.1 — CPU/GPU 온도 표시 확대

기존 오른쪽 컴퓨터 온도 패널과 함께 창 상단 요약, 트레이 우클릭 메뉴에도 현재 온도를 표시한다.
같은 센서 값/신선도 검사를 사용하며 약 2초마다 갱신한다. 센서 조회가 지연 중이어도 표시 만료를 검사한다.
실물 CPU 57~58°C/GPU 47°C에서 WPF 상단/패널/트레이 요약 일치, 자동 제어/복원과 화면 배치를 확인했다.
로컬과 GitHub의 전체 Release 빌드/34개 테스트, v0.4.1 게시와 공개 ZIP/EXE 다운로드 해시 검증을 통과했다.
현재 PC에는 해당 버전을 설치하고 사용자가 선택한 로그인 CPU/GPU 자동 제어 On을 유지한다.

## 0.4.0 — 로그인 자동 실행, 트레이와 아이콘

현재 사용자 로그인 후 10초 지연 예약 작업을 등록하고 Program Files 사본을 최고 권한으로 실행한다.
CPU 센서 권한을 유지하면서 대화형 세션의 트레이에서 동작하며 SYSTEM 서비스/암호 저장을 사용하지 않는다.
별도 설치 스크립트가 EXE 해시를 확인하고 보호된 경로에 복사한 뒤 바탕화면/시작 메뉴 바로가기를 만든다.
자체 SVG 팬 아이콘을 9개 해상도의 ICO로 생성해 실행 파일/창/트레이에 포함한다.

앱 시작·숨김과 센서/USB 초기화를 분리했다. X/최소화는 숨기기이며 자동 제어는 유지한다.
명시적 종료는 기존 비동기 복원/연결 정리 후 트레이까지 제거한다. 기존 창 열기와 고정 상태/종료 명령만
전용 Windows 메시지로 허용하며 임의 명령/파일 경로를 관리자 프로세스에 전달하지 않는다.
일반 사용자 실행은 기존 관리자 창을 열거나 등록 작업을 시작한다. 사용자별 mutex로 중복 실행을 막는다.

자동 실행 시 온도 제어 여부와 기준/곡선을 로컬 JSON에 저장한다. 기본값은 앱만 시작한다.
온도 자동 시작을 선택했으면 센서와 USB가 준비된 뒤 시작하고 기존 고온/센서 만료 보호를 사용한다.
같은 예약 작업 실행, 일반 사용자 바로가기 동작, 단일 실행, 숨김 자동 제어와 종료 시 복원을 실기 검증했다.
실제 재부팅/로그아웃/절전 복귀는 시험하지 않았다. 세션 종료 시 복원은 최선의 시도이며 강제 종료 복원과 구분한다.
[자동 실행 및 트레이 상세](DESKTOP-STARTUP.ko.md)

아래 버전의 창 닫기/관리자 요청에 대한 설명은 당시 동작의 이력이다. 0.4.0의 X는 트레이로 숨긴다.

## 0.2.1 — 공식 CPU 센서 설정 및 권한 재실행

사용자 허용에 따라 공식 서명 PawnIO 2.2.0을 설치하고 Intel CPU Package 온도를 실제로 읽었다.
일반 권한에서 CPU 접근 거부를 확인해 앱에 CPU 권한으로 다시 실행하는 버튼을 추가했다.
드라이버의 접근 권한을 모든 사용자에게 열지 않고 공식 기본 설정을 유지한다.
기본 온도 기준은 CPU/GPU 중 높은 값이며 임시 목표 RPM은 약 1초마다 갱신한다.
앱 자체는 드라이버를 설치/시작하지 않고 버튼을 직접 누를 때만 관리자 실행을 요청한다.
실기에서 CPU 78°C / GPU 50°C의 높은 CPU 기준으로 목표 2700 RPM과 실제 2600 RPM 상승을 확인했다.
중지 후 기존 목표 1400 RPM/저장 속도 복원과 WPF CPU/GPU 자동 제어 시험도 통과했다.
[현재 자동 제어 상세](AUTOMATIC-COOLING.ko.md)

아래 0.2.0/0.1.0의 CPU 미설정 및 관리자 요청 없음 설명은 당시 버전의 이력이다.

## 구현

제조사 프로그램에 대한 보안 우려를 반영해 제조사 코드의 로드/실행 경로를 제거했다.
배포 앱은 자체 .NET 코드와 Windows 기본 HID API로 BS2 Pro를 직접 제어한다.

| 프로젝트 | 역할 |
| --- | --- |
| `src/Bs2Cooler.Core` | 명령 생성, 길이/체크섬 검증, RPM/상태 해석 |
| `src/Bs2Cooler.Windows` | 장치 열거, 인터페이스 검증, 비동기 USB I/O |
| `src/Bs2Cooler.App` | 한국어 WPF 화면, 주기적 조회, 수동 설정, 재검색 |
| `tests/Bs2Cooler.Tests` | 실제 캡처 패킷, 손상/절단/경계값 테스트 |
| `tools/Bs2Cooler.Diagnostics` | 읽기 전용 조회, 변경/복원 실기 시험 |
| `tools/Bs2Cooler.UiSmoke` | WPF 연결/실제 데이터/최소 크기 레이아웃 검증 |

외부 패키지 참조는 0개다. 제조사 DLL/프로세스/IPC와 HidSharp를 사용하지 않는다.
네트워크 클라이언트, 외부 프로세스 실행, 드라이버/서비스 설치, 자동 업데이트,
관리자 권한 요청도 없다. 네이티브 DLL 검색은 System32로 제한하고
`hid.dll`, `setupapi.dll`, `kernel32.dll`만 직접 호출한다.

`.analysis/`의 초기 비교용 프로젝트는 제조사 SDK를 실행했던 이전 분석 자료다.
새 앱/테스트/진단의 빌드·실행에 필요하지 않고 배포에도 포함하지 않는다.
기존 프로그램의 악성 여부와 기존 PC 감염 유무는 이 통신 구현으로 판정하지 않는다.

## 통신 및 정확성

- 실물 USB `37D7:1002`, Usage `FFA0:1`, 펌웨어 `0.0.3.3`
- 입력 33바이트(`00 03 5A A5`), 출력 32바이트(`00 5A A5`)
- 수신 길이/가산 체크섬 검증, 명령 직렬화 및 명령 ID 일치 확인
- 1.5초 응답 제한, 비동기 읽기 취소/연결 종료 처리
- 6초 내 전원 상태가 없거나 쿨러가 꺼져 있으면 속도 변경 거부
- 전원에 따른 RPM 상한 검증, 시작/재연결 시 설정 쓰기 없음

단독 RPM 명령 `0x21`은 실물 수동 모드에서 응답 `2`로 거부됐다.
앱은 수동 제어 성공이 확인된 **단계+RPM 명령 `0x26`만 사용**한다.
처음 시험에서 이 거부로 조명 복원이 중단됐으나 즉시 기존 설정을 복원했다.
진단의 복원 작업을 각각 독립적으로 수행하도록 수정한 뒤 전체 시험을 다시 통과했다.

## 남은 조건

실물 시험은 일반 전원(최대 2700 RPM), 수동 모드, 이미 켜진 USB 장치에서 수행했다.
QC/PD 고속 회전, 스마트 모드 해제, 실제 케이블 분리/절전 복귀,
장치 전원까지 껐다 켜는 냉간 시작은 아직 실기 시험하지 않았다.
이 조건의 오류/재검색/상한 처리는 구현된 부분과 실물 검증된 부분을 구분한다.

온도 센서/자동 곡선, Bluetooth, RGB 색상/효과 편집, 펌웨어 업데이트는 이 버전의 범위 밖이다.
쿨러 수동 제어를 위해 별도 드라이버를 설치하지 않는다.

Windows HID 버퍼 규칙은 [Microsoft HIDP_CAPS 문서](https://learn.microsoft.com/en-us/windows-hardware/drivers/ddi/hidpi/ns-hidpi-_hidp_caps)에 따라 구현했다.
